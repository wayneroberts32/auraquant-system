🧩 Data Source Rules

The system must operate primarily as a stand-alone platform using our broker APIs through the Render backend.

All quotes, candles, market depth, accounts, orders, and positions must come from our broker APIs.

Health checks must be performed on all broker connections. If latency rises above 1.5x baseline, if error rates exceed 2%, or if heartbeat signals are delayed more than 3 seconds, the system must mark the connection as DEGRADED.

If a broker connection is lost, the system must enter FAILOVER mode. In FAILOVER, all trading functions are disabled, and the frontend must fall back to TradingView or Plus500 data as a read-only view.

In FAILOVER, display a clear but non-intrusive banner at the top of the screen:

“Primary broker data unstable. Viewing fallback feed. Trading is temporarily disabled.”

Once the broker health checks return to stable, the system must automatically recover back to Primary mode, and the banner must disappear.

In the bottom status bar, display a status dot:

🟢 Green = Primary data

🟠 Amber = Degraded

🔵 Blue = Fallback

🟢 Green again = Recovered
